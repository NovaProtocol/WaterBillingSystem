# API Contract

## Overview

The WaterBillingSystem REST API is served by the **API container** (port 8008, internal). All endpoints are under `/api/*` unless noted. Responses are JSON.

**Base URL (internal)**: `http://api:8008/api`

All endpoints that require an API key accept it via:
- `Authorization: Bearer <key>` header
- `?api_key=<key>` query parameter

## Authentication

### API Keys

Format: `CRDC-` + 32 uppercase hex characters. Generated by staff from the Meter Reading page. Tied to a specific staff account with associated permissions.

| Method | Example |
|--------|---------|
| **Bearer Header** | `Authorization: Bearer CRDC-A1B2C3D4E5F67890A1B2C3D4E5F67890` |
| **Query Parameter** | `?api_key=CRDC-A1B2C3D4E5F67890A1B2C3D4E5F67890` |

### Internal API Key

Used for service-to-service communication between containers. Sent via:
- `X-Internal-API-Key` header + `X-Staff-ID` (set by `staff-portal/api_client.py` from the portal's JWT)

When an internal API key is provided (matching `INTERNAL_API_KEY` env var), the API re-derives the staff from `X-Staff-ID` and re-checks `require_staff(*perms)` with OR semantics — no blanket bypass. `GET /api/debug/*` requires `can_enroll_staff`.

### Staff Session Login

`POST /api/staff/login` returns staff data. Portals sign sessions with `PyJWT HS256` (`shared/wbs_jwt.py` `ISS=wbs AUD=waterbillingsystem` — customer `billing_session` 12h `Path /customer/` `HttpOnly SameSite=Lax Secure`, staff `session` 8h, dev `session` 8h). `shared/auth.py` is a one-deploy itsdangerous fallback only.

### 12. POST /api/customer/{customer_number}/invoice

Create a Xendit payment session for online payment. The `xendit_fee` from the selected PaymentMethod is added to the `total_amount` sent to Xendit. `success_url` and `cancel_url` are forwarded from the request through to the Xendit API.

**Auth**: Internal

**Request body**:
```json
{
 "amount": 724.0,
 "payment_method": "gcash_ewallet",
 "success_url": "https://example.com/success",
 "cancel_url": "https://example.com/cancel"
}
```

**Response 200**:
```json
{
 "redirect_url": "https://checkout.xendit.co/session/...",
 "external_id": "wbs-1-1712345678-a1b2c3d4",
 "id": "sess_123",
 "base_amount": 724.0,
 "fee_amount": 21.72,
 "fee_rate": 3.0
}
```

**Response 400**: `{"error": "Invalid amount"}`
**Response 503**: `{"error": "Xendit not configured"}`

### 37–49. Debug Endpoints

All debug endpoints require superuser access (checking `/app/db_backups` directory existence). All destructive operations run via the background task queue.

#### GET /api/debug/stats

Returns record counts across all database tables.

**Response 200**:
```json
{
 "customers": 150, "customers_total": 160,
 "readings": 4800, "billings": 4800,
 "unpaid_bills": 150, "paid_bills": 4650,
 "staff": 5, "api_keys": 3,
 "nfc_tags": 150, "management_logs": 25,
 "xendit_transactions": 10, "payment_methods": 6,
 "background_tasks": 42
}
```

#### POST /api/debug/backup
Queue a database backup. Returns task ID.
```json
{"ok": true, "order_id": 1, "message": "Backup queued."}
```

#### GET /api/debug/backups
List available backup files.
```json
{"backups": [{"name": "backup_20260721_120000.sql", "size": 102400, "modified": "2026-07-21T12:00:00"}]}
```

#### POST /api/debug/restore
Queue a restore from a specific backup file.
```json
{"filename": "backup_20260721_120000.sql"}
```

#### GET /api/debug/restore-newest
Restore from the newest backup (5-second cooldown per request).

#### POST /api/debug/clear
Queue a full database clear. Preserves system staff accounts.

#### POST /api/debug/seed
Queue test data seed.
```json
{"customers": 100, "months": 12}
```
Customer count: 1–10000. Months: 1–240.

#### POST /api/debug/read-month
Create readings + unpaid bills for all customers without a current month reading.

#### POST /api/debug/unread-month
Remove current month unpaid readings.

#### POST /api/debug/pay-month
Mark all unpaid current-month bills as paid.

#### POST /api/debug/remove-pay-month
Revert all paid current-month bills to unpaid.

#### GET /api/debug/tasks
Full task queue status.

```json
 "status": "running", "progress": 42.5,

 "queue_depth": 0,
 "history": [...]
}
```

#### GET /api/debug/tasks/{task_id}
Single task details, including params and result.

All endpoints return errors as:
```json
{"error": "Description of what went wrong"}
```

| Code | Meaning |
|------|---------|
| 200 | Success |
| 201 | Created |
| 400 | Bad request |
| 401 | Authentication required |
| 403 | Permission denied |
| 404 | Not found |
| 409 | Conflict (duplicate) |
| 429 | Rate limited |
| 500 | Internal server error |
| 502 | Upstream error (Xendit) |
| 503 | Service unavailable |
