# API Reference

All REST API endpoints are prefixed with `/api` and defined in `apps/api/`. Authenticated endpoints require an active API key (`CRDC-<32hex>`).

## Authentication

### API Key Auth

Keys are generated by staff from the Meter Reading page (`/staff/meter-reading`). Format: `CRDC-` + 32 uppercase hex characters.

=== "Bearer Header"
    ```
    Authorization: Bearer CRDC-A1B2C3D4E5F67890A1B2C3D4E5F67890
    ```
=== "Query Parameter"
    ```
    GET /api/customer/123?api_key=CRDC-A1B2C3D4E5F67890A1B2C3D4E5F67890
    ```
=== "Session Cookie"
    ```
    Cookie: session=...
    ```
    (Only for `/api/customer/:num` — requires Flask-Login session)

### Key Resolution Order

1. `Authorization: Bearer <key>` header
2. `?api_key=<key>` query parameter
3. Flask-Login session (staff portal login)

Only active (non-revoked) keys are accepted.

### 1. GET /api/health

Check database connectivity.

### 6. POST /api/readings/sync

Bulk upload multiple readings. Used by MeterReadingApp to sync offline-collected readings.

**Endpoint**: `<ServerURL>/api/readings/sync`

**Auth**: API key — `Authorization: Bearer <key>` header or `?api_key=<key>` query param

**Payload**:
```json
{
  "readings": [
    {"customer_number": "C1", "reading_value": 280.5, "timestamp": 1779000000},
    {"customer_number": "C2", "reading_value": 150.2}
  ]
}
```

| Field | Type | Required | Default | Description |
|---|---|---|---|---|
| `customer_number` | string | yes | — | Must exist in DB |
| `reading_value` | number | yes | — | Meter reading in m\u00b3 |
| `timestamp` | int | no | current time | Unix timestamp |

Reader is auto-resolved from the API key's associated staff member. Monthly duplicate check: If a reading already exists for the same customer in the same calendar month, it is rejected and logged to `ManagementLog`.

**Response** `200` — partial success:
```json
{
  "synced": 1,
  "total": 2,
  "results": [
    {"index": 0, "reading_id": 42, "customer_number": "C1"}
  ],
  "errors": [
    {"index": 1, "error": "This meter has already been read this month"}
  ]
}
```

**Response** `200` — all accepted:
```json
{
  "synced": 2,
  "total": 2,
  "results": [
    {"index": 0, "reading_id": 42, "customer_number": "C1"},
    {"index": 1, "reading_id": 43, "customer_number": "C2"}
  ],
  "errors": []
}
```

**Response** `400` — missing required field:
```json
{"error": "readings field is required"}
```

**Response** `401` — missing or invalid API key:
```json
{"error": "Authentication required"}
```

### 9. GET /api/customers/changed

Change detection — returns customer numbers modified since a timestamp. Used by MeterReadingApp for incremental sync.

**Endpoint**: `<ServerURL>/api/customers/changed`

**Auth**: API key — `Authorization: Bearer <key>` header or `?api_key=<key>` query param

**Query params**: `?since=<unix_timestamp>` (required)

Detects changes from:
- Customer profile modifications (`date_modified`)
- New or edited meter readings
- Readings dropped (via `ManagementLog` entries)

**Response** `200` — changes found:
```json
{
  "customer_numbers": ["C1", "C5"],
  "server_time": 1718841600,
  "total_customers": 20
}
```

**Response** `200` — no changes:
```json
{
  "customer_numbers": [],
  "server_time": 1718841600,
  "total_customers": 20
}
```

**Response** `400` — missing `since` parameter:
```json
{"error": "since parameter is required"}
```

**Response** `401` — missing or invalid API key:
```json
{"error": "Authentication required"}
```

### POST /billing/api/lookup

Look up a customer using their customer number and most recent receipt number.

**Endpoint**: `<ServerURL>/billing/api/lookup`

**Auth**: None (rate-limited to 10 requests per minute per IP)

**Payload**:
```json
{
  "customer_number": "C1",
  "last_receipt": "RCP-1712345678-ABCD"
}
```

**Response** `200` — customer found:
```json
{
  "customer_number": "C1",
  "name": "Juan Dela Cruz",
  "address": "123 Rizal St., Brgy. San Jose",
  "contact_number": "09123456789",
  "email": "juan.delacruz1@email.com",
  "x_coordinate": 14.6,
  "y_coordinate": 120.95,
  "cumulative_balance": 0.0
}
```

**Response** `400` — missing customer number:
```json
{"error": "Customer number is required"}
```

**Response** `403` — receipt mismatch:
```json
{"error": "Receipt number does not match our records"}
```

**Response** `404` — customer not found:
```json
{"error": "Customer not found"}
```


## Error Responses

All endpoints return errors in the same format:
```json
{"error": "Description of what went wrong"}
```

| Status | Meaning |
|---|---|
| `200` | Success |
| `201` | Created |
| `400` | Bad request (missing/invalid parameters) |
| `401` | Authentication required / invalid API key |
| `403` | Permission denied / inactive key |
| `404` | Resource not found |
| `409` | Conflict (e.g., duplicate month) |
| `500` | Internal server error |
