# BillServer REST API Reference

**Base URL**: `/api` (e.g., `http://localhost:5005/api/...`)
**Content-Type**: `application/json`

---

## Authentication

Three methods supported:

| Method | Example |
|--------|---------|
| **Session (Flask-Login)** | Staff login cookie from `/staff/login` |
| **Bearer Token** | `Authorization: Bearer CRDC-...` |
| **Query Parameter** | `?api_key=CRDC-...` |

API keys are generated by authorized staff at `/staff/meter-reading`. Keys use the prefix `CRDC-` followed by 32 hex characters (uppercase). Keys can be revoked (soft-delete via `is_active = False`).

## Implemented Endpoints

Check database connectivity. No auth required.

**Response** `200`:

### `POST /api/readings/sync`

Bulk-sync meter readings from mobile device.

**Auth**: API key + `can_read_meters`

**Request**:
```json
{
  "readings": [
    {"customer_number": "C1", "reading_value": 280.5, "timestamp": 1779000000},
    {"customer_number": "C2", "reading_value": 150.2}
  ]
}
```

The `timestamp` field is optional (defaults to current time). The reader name is resolved from the API key's associated staff member.

**Monthly duplicate check**: If a reading already exists for the same customer in the same calendar month, it is rejected and logged to `ManagementLog`.

**Response** `200`:
```json
{
  "synced": 1,
  "total": 2,
  "results": [
    {"index": 0, "reading_id": 42, "customer_number": "C1"}
  ],
  "errors": [
    {"index": 1, "error": "This meter has already been read this month"}
  ]
}
```

### `POST /api/readings/upload`

Upload a single meter reading.

**Auth**: API key + `can_read_meters`

**Request**:
```json
{
  "customer_number": "C1",
  "reading_value": 310.2,
  "timestamp": 1779100000
}
```

**Response** `201`:
```json
{
  "success": true,
  "reading_id": 481,
  "customer_number": "C1",
  "reading_value": 310.2,
  "timestamp": 1779100000,
  "reader": "Superuser"
}
```

**Errors**: `400` — missing fields, `404` — customer not found, `409` — duplicate month

### `GET /api/customers/changed`

Change detection — returns customer numbers modified since a timestamp. Used by MeterReadingApp for incremental sync.

**Auth**: API key + `can_read_meters`

**Query params**: `?since=<unix_timestamp>` (required)

**Errors**: `400` — `{"error": "since parameter is required (Unix timestamp)"}` if since parameter is missing

Detects changes from: customer profile modifications, new/edited meter readings, and readings dropped via ManagementLog.

**Response** `200`:
```json
{
  "customer_numbers": ["C1", "C5"],
  "server_time": 1718841600,
  "total_customers": 20
}
```

---

### `GET /api/readings/bulk`

Fetch multiple customers with reading history. Used for batched data sync (500 customers per request).

**Auth**: API key + `can_read_meters` (max 5000 customer numbers per request)

**Query params**: `?customer_numbers=C1,C2&limit=5`

**Response** `200`:
```json
{
  "customers": {
    "C1": {
      "customer": {
        "customer_number": "C1",
        "name": "Juan Dela Cruz",
        "address": "123 Rizal St., Brgy. San Jose",
        "contact_number": "09123456789",
        "phase": "Phase 1",
        "block": "Block A",
        "street": "Rose St",
        "x_coordinate": 14.6,
        "y_coordinate": 120.95,
        "nfc_uid": "045A6BC2DEF180"
      },
      "readings": [
        {"id": 480, "reading_value": 250.6, "reader": "Juan Dela Cruz", "timestamp": 1778968800}
      ]
    }
  }
}
```

The `nfc_uid` field is `null` if the customer has no registered NFC tag. The phone computes the PWD_AUTH password locally from `nfc_pwd_secret` + UID.

## NFC Tag Endpoints

### `GET /api/nfc/config`

Returns the NFC_PWD_SECRET for offline password computation on the phone. Called once during initial setup.

**Auth**: API key + `can_read_meters`

**Response** `200`:
```json
{
  "nfc_pwd_secret": "REDACTED_SET_VIA_NFC_PWD_SECRET_ENV",
  "nfc_generation": 0
}
```

---

### `POST /api/nfc/clear`

Clears all NFC tag mappings and increments the NFC generation counter, invalidating all existing tags. Touches `Customer.date_modified` for all customers so change detection triggers a full re-download.

**Auth**: API key + `can_enroll_customer`

**Response** `200`:
```json
{
  "cleared": 42,
  "message": "Cleared 42 NFC tag(s)"
}
```

---

### `POST /api/nfc/sync`

Upload NFC tag enrollments from the mobile app. Staff must have `can_enroll_customer` permission.

**Auth**: API key + `can_enroll_customer`

**Request**:
```json
{
  "enrollments": [
    {"uid": "045A6BC2DEF180", "customer_number": "C1"}
  ]
}
```

**Response** `200`:
```json
{
  "synced": 1,
  "total": 1,
  "errors": []
}
```

Also touches `Customer.date_modified` so change detection picks up the new NFC tag on next sync.

---

### `GET /api/nfc/tags`

Returns all registered NFC tag mappings. Used by the phone to populate its local `nfc_cache` table.

**Auth**: API key + `can_read_meters`

**Response** `200`:
```json
{
  "tags": [
    {"uid": "045A6BC2DEF180", "customer_number": "C1"}
  ]
}
```

## Billing Page Endpoints (Cookie-Auth)

These are served via the `/billing` blueprint and require a cookie set by the landing page confirmation flow.

| Method | Endpoint | Description |
|---|---|---|
| POST | `/billing/api/lookup` | Customer lookup by number + receipt verification |
| POST | `/billing/api/confirm` | Confirm identity, set cookies, redirect |
| GET | `/billing/api/:num/readings` | Paginated readings (`?page=N&per_page=N`) |
| GET | `/billing/api/:num/payments` | Paginated payments |
| GET | `/billing/api/:num/history` | Paginated billing history |

---

## Error Responses

All endpoints return standardized error JSON:
```json
{"error": "Description of what went wrong"}
```

**HTTP status codes**:

| Code | Meaning |
|------|---------|
| `200` | Success |
| `201` | Created |
| `400` | Bad request (missing/invalid fields) |
| `401` | Authentication required / invalid API key |
| `403` | Permission denied / inactive key |
| `404` | Resource not found |
| `409` | Conflict (duplicate resource) |
| `500` | Internal server error |
